# Vorntek 0.2.0-rc.5 — configurable acquisition and operations sync

This candidate supersedes `0.2.0-rc.4`. It brings the reusable acquisition and
operations improvements proven in a separate customer installation back into the
industry-neutral Vorntek product without copying customer records, credentials,
runtime configuration or private operational history.

## Product changes

- Public inquiry forms use locale-aware configurable field definitions. Each
  accepted submission retains the exact schema snapshot used for its validation,
  so later form edits do not rewrite historical meaning.
- CRM operators get one persistent PC navigation shell, denser lead pages and
  explicit batch selection. Selection is cleared or revalidated across paging so
  an action cannot silently target records from another page.
- Customer-pool and lead exports enforce authorization, bounded output and safe
  spreadsheet cells. Standard-21 imports preserve site ownership, reject unsafe
  cross-site reuse and use explicit final-state constraints.
- Guided marketing supports multiple independent instances of the same workflow,
  consistent manage/guide routing, flow diagrams and the complete illustrated
  operation guide.
- The bundled industrial website remains replaceable example content and reads
  the configured public inquiry contract instead of a fixed industry schema.

## Upgrade boundary

Migrations `0044`–`0047` append locale contracts, export claim generation,
immutable customer ownership and customer-pool final-state constraints. Existing
installations must follow `docs/UPGRADE.md`, preserve their project/volume/secret
identities and keep all external writers disabled during preflight and migration.
Applied migration files and historical ledger rows must not be changed.

## Non-claims

This source release does not enable external Meta, Google, email or WhatsApp
delivery and does not certify provider reception, advertising attribution or
deduplication. It ships no production credentials, customer data, private backup,
prebuilt image, multi-node failover or availability SLA. Public-source acceptance
and a running Vorntek deployment are recorded as separate evidence.
