## Anonymous installation and tests

A new Python 3.12 virtual environment and isolated Node dependency tree were
created inside the extracted public archive. `scripts/configure.py` generated new
local file-backed secrets; no development virtual environment, source checkout,
production configuration or production credential was reused.

- Dependency consistency: `pip check` passed.
- Python vulnerability audit: no known vulnerabilities.
- Root Python: 118 passed; eight Git-only checks skipped as documented for source
  archives without `.git` metadata.
- Application: 1379 passed; 140 documented SQLite conditional skips.
- Root JavaScript: 51 passed.
- Guided-loop JavaScript: 209 passed.
- Node dependency audit: zero vulnerabilities at the configured moderate threshold.
- Vite production build: passed and generated all sixteen customer-neutral guide
  figures.

The same public archive then ran its loopback-only browser fixture. The configurable
general inquiry fields loaded, the industrial product detail rendered, and the
interactive 3D equipment model visibly started. No inquiry was submitted. Fixture
shutdown reported synthetic data only, external I/O disabled, zero imports and
zero exports; its credential file was removed.

## Authorized Vorntek production upgrade

The exact merge commit was deployed to the authorized Vorntek installation after
a fresh paired backup and an isolated restore drill. The isolated PostgreSQL gate
verified 47-to-47 repeatability, fresh installation, read-only planning, schema
parity, rollback and all six release acceptance groups without modifying the live
database.

Final read-only production verification observed:

- application/worker image
  `sha256:4a1878514ae988d69b1ecfab0298e379d4868f0bed7962760578ac471eb70b0c`;
- website image
  `sha256:bfbff73ec124487db352a160cd2e87fa6e83120f24b914ec096a25a60ab28105`;
- five healthy containers and health version `0.2.0-rc.5`;

- `NEWCROWN_ALLOW_EXTERNAL_IO=0`, `NEWCROWN_RUN_SCHEDULED_TASKS=0` and
  `SITEOS_WHATSAPP_ALLOW_LIVE_SEND=0` on CRM, export and scheduler services.

Real-browser review covered the English public site and form without submission,
the CRM lead workbench and reversible batch selection, locale-specific form
configuration, three guided-loop instances, flow/task views and operation figures.
One disabled locale probe was created and removed during the review.

The append-only audit log correctly prevented physical deletion of the temporary
review actor. To preserve that immutable history, the actor remains as one inactive,
non-staff, non-superuser account named `browser_acceptance_tombstone`, with no
groups, no permissions and an unusable password. The local credential file was
deleted. This is an audit identity, not a login-capable operator.
